Continuous performance results, in context.

How it works

Measure, publish, and inspect.

01

Run benchmarks anywhere

Your harness owns execution. BenchDB accepts result files from CI, scheduled fleets, or local experiments without dictating the benchmark framework.

02

Publish structured results

The CLI sends measurements with run, commit, machine, unit, and benchmark identity. Publication can retry without repeating the measurement.

03

Decide with history

Inspect trends across the fleet, compare results, and use history-aware CI reports to separate meaningful changes from ordinary noise.

Result history

Trace a measurement to its context.

BenchDB keeps measurements connected to the benchmark case, run, repository commit, machine, unit, and comparable history. Start with the signal and move to detail without reconstructing context from CI logs.

Interfaces

Use the browser, CLI, or API.

CLI

Command-line client

Submit files, create CI reports, compare results, list series, and export histories from one binary.

API

OpenAPI

Use the HTTP contract directly or generate integrations in the language your systems already use.

WEB

Web interface

Browse activity, trends, machines, results, and comparisons without reading raw payloads.

ALERT

Scheduled alerts

Evaluate regression rules separately from delivery so monitoring fits your existing job system.
